# v3.9.56（2026-11-20）

## 问题
task-d31e6e1305（用 Antigravity 复刻 ldok.top）：三个 agy 任务（agy-11200120-3f7d / -9524 / -72a8）都是「无改动、denied 1、报告空」，每个还空等了 1 小时才结束。AIW 随后自己在 shell 里跑了 `agy --print --dangerously-skip-permissions`，并三次改了 `~/.gemini/antigravity-cli/settings.json`。

## 原因（来自 events.jsonl 和 ~/.gemini/antigravity-cli/log/cli-*.log）
1. **读 worktree 外的文件被拒**：agy 的 workspace 是 `~/workspace/.aiw-worktrees/ldok-rebuild/<job>`，任务里写的却是 `/home/aiw/workspace/ldok-rebuild/mirror/...` 和 `~/.claude/skills/...`。headless 下这类 read_file 被 soft-deny（`soft-denying tool confirmation "ReadFile"`），即使加了 `read_file(**)` 也一样。同一仓库直接当 workspace 时（cli-20261120_012414）读文件 92 步都没问题。
2. **规则名字写错被静默忽略**：agy 只认 `read_file`、`write_file`、`command`。`bash`、`shell`、`run_command`、`edit_file`、`apply_patch`、`glob`、`grep_search`、`list_directory` 全部 `unknown action`，被忽略。
3. **被拒后空等**：拒绝后 agy 回合结束、回复为空，bridge 保持会话 60 分钟等追问（`end_reason: expired`）。
4. **报告空**：模型被拒时没说话；bridge 只记了通用的拒绝文本，没说是哪一步、哪个文件。
5. **没有约束**：没有任何规则禁止 AIW 直接跑 agy、加 `--dangerously-skip-permissions` 或改 agy 设置。
6. `policy.py` 的 `\bqm\s+` 把 `git commit -qm` 当成 Proxmox 命令（L4）拦下。

## 改动
- `agy_bridge.py`（bridge 版本 2）
  - `stage()`：任务和追问里的绝对路径：仓库内 → worktree 同一路径；只在外面有的（技能整个目录、未提交文件）→ 复制到 `<worktree>/.aiw-context/`（自带 `.gitignore: *`，上限 60 MB），并在提示末尾列出映射。
  - 拒绝记录改为结构化：`{action, tool, target, outside_worktree, why}`；该回合状态 `blocked`，回复为空时自动写明哪一步被拒；`blocked` 会话最多保留 10 分钟（仍可 `send` 追问）。
  - `settings` 子命令：没有设置文件或 `aiwManaged: true` 时写入 AIW 默认规则（只用合法动作；放开 mkdir/cp/mv、运行 `python3 x.py`、`npm install` 等常用开发命令；禁止 git push、sudo、碰 `.gemini/` 和 `.config/aiw/`、`--dangerously-skip-permissions`）。用户已有的、非 AIW 管理的设置不覆盖，只报告被忽略的规则。`settings --reset` 先备份再恢复默认（保留其他键、去掉 dangerouslySkipPermissions），只给用户在终端里跑。
  - `check` / `start` / `wait` 返回 `settings`（被忽略的规则、是否全自动批准）和 `staged`。
- `antigravity.py`：默认规则改从 bridge 取；安装命令不再出现 `.gemini` 路径；简报要求用相对路径、不要 `cd x && ...` 连写；`blocked` 时的下一步：禁止绕过，路径问题就把 worktree 内路径 send 回去，否则 ask_user 并引用被拒的那一步；AIW 自己做完的要告诉用户「不是 Antigravity 做的」。
- `loop.py`：`blocked` 视为失败步骤；步骤卡片显示被拒的那几步。
- `policy.py`（L4）：shell 里以命令形式运行 `agy`、`--dangerously-skip-permissions`、读写 `~/.gemini/...settings`、`agy_bridge.py settings --reset`；files 写 `.gemini/`、`.config/aiw/agy/`。`qm`/`pct` 只在命令位置才算 Proxmox。
- 测试：`tests/test_v3956_agy_permissions.py`（14 个），fake_agy 模拟真实的 read_file 拒绝；`test_v3954_antigravity.py` 按新行为更新。

## 未验证

- `write_file(~/.gemini/**)` 这种带 `~` 的拒绝规则写法 agy 是否认（动作合法，不会被忽略；路径语法未确认）。
