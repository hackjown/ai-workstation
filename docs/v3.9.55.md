# v3.9.55（2026-11-20）

## 问题
开发、修复代码的任务被分到了「设计制图」云电脑。用户要求：凡是与代码有关的任务都在本地 VM（ai-linux-001，已装 Antigravity）上执行。

## 原因
`aiw_api/roles.py` 按关键词给新任务挑云电脑，本地 VM 默认不参与（`exclude_local: true`，只接家里内网的活）。
- 「设计制图」的关键词里有 图片、png、jpg、ui、logo、设计稿；代码任务一提到页面图片、logo、UI，就按设计算分。
- 即使选了 dev 技能，也只会去「办公·网页·开发」云电脑，永远不会到本地 VM。

## 改动
- `roles.py`：新增 `is_code()`（dev 技能 / agent 自己的 dev_fix 意图 / 代码关键词：代码、bug、报错、调试、编译、打包、脚本、程序、git、仓库、python、接口、前后端、apk、antigravity、`.py/.js/...` 文件名等；视频脚本、文案、开发票不算）。`pick()` 里代码任务直接去本地 VM，排在关键词角色之前；本地忙也在本地排队，不改派云电脑。只有用户在请求里点名某台电脑时才去那台。
- 多台本地电脑时用 `machine_roles.code_machine` 指定，默认第一台本地电脑；填云电脑 id 无效。
- 本地 VM 的角色显示为「代码开发」（任务卡片：本地VM · 代码开发）；多机并行（dispatch）里本地 VM 不再被排除，代码子任务自动分到它。
- 开关 `machine_roles.code_to_local`（默认开）。`PUT /api/machine_roles` 支持 `code_to_local`、`code_machine`；命令行 `aiw-roles.sh code on|off [本地电脑]`，`aiw-roles.sh test <任务文字>` 会显示 `code: true/false`。
- `tests/test_v3955_code_to_local.py`（7 个）；`test_v390_fix_roles.py` 两处断言按新行为更新。

## 不变
- 「继续 / 修改」接着原任务所在的电脑做（文件在那台上）。之前在设计云电脑上开始的代码任务，继续时还在那台；新开一个任务就会到本地。
- 定时任务、比价监控、小红书保持原来设好的电脑。

## 测试
- 新增 7 个测试通过；角色相关的其他测试文件改动前后失败项完全相同（都是沙箱环境问题）。
