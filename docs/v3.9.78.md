# v3.9.78 Muse 密钥和权限（3.9.78 build 52）

## META_API_KEY 不再走命令行
- 以前密钥放在 job 里，经 `cli_bridge.py start --job-b64 …` 传到电脑，`ps` 能看到，还写进 job.json。
- 现在 AIW 用新命令 `setenv` 把引擎密钥写到电脑上的 `~/.config/aiw/cli/env/<引擎>.json`（目录 0700、文件 0600），只在密钥变了或桥接脚本重装后写一次；job 和 job.json 里不再有密钥。
- 每一轮启动 muse 时，桥接脚本从这个文件读出环境变量。`~/.config/aiw/**` 本来就在拒绝清单里，引擎读不到。
- 旧版 AIW 仍在 job 里带 env 时，桥接脚本会把它转存到 env 文件并从 job.json 去掉。

## Muse 的权限和拒绝清单
- 每台电脑第一次跑 muse 时读一次 `muse exec --help`：有 `--deny` 就像 Grok 一样逐条传 v3.9.75 拒绝清单；有 `--disallowed-tools` 就按 Claude 格式传；有 `--disable-approval` 就加上，避免无人值守时卡住或把写文件全拒掉。从不加 `--yolo`。
- 不管有没有这些参数，提示词开头都带上 AIW 规则（只在工作文件夹读写、拒绝的命令和路径），作为兜底。

## 测试
- `tests/test_muse_cue_engines.py` 新增 4 个用例：密钥不进 job 和 start 命令、只写一次；env 文件 0600；有参数时的 argv；没参数时仍带规则。
