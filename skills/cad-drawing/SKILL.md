# 照图 / 按描述出图（cad-drawing）

像一个靠谱的工程师那样画图：**先把源图读准、记下来，再一次性生成；错了改 spec 重新生成，不在图上打补丁。**

本文件夹：`drawkit.py`（读图 + 生成 + 检查的一体化工具）、`drawtrace.py`（3.9.2 确定性描图 + 与原图比对）、`drawauto.py`（墙网格草稿，描图器读不了的图用它）、
`examples/xinda-g-108.spec.json`（**通用示例**，只用来看 spec 怎么写：信达海天下 G 户型照片 → spec）、
`examples/12-031de1aca2dd.JPG`（示例的原图）。

## 3.9.2：确定性描图 + 硬核对 + DWG（task-778 之后，优先于下面的旧流程）
task-778：照片只有总尺寸「约9800 / 约10900」，视觉模型估的墙像素偏了 500–700 mm，房间被硬塞进三排网格，还编出一个
「主卧过道」；旧的 overlay 核对却报 91/91 对上。所以现在：
- **读图不用视觉模型。** `drawing_auto`（= `drawkit.py auto`）先跑 `drawtrace.py`：
  - 比例：RapidOCR 读尺寸数字（总尺寸或分段链都行，竖排自动旋转），在像素里找它的尺寸线和刻度，**刻度到刻度**量 px → mm/px，横竖各一个。
  - 墙：深色像素做形态学开运算（细线、文字、家具线全部去掉）→ 横墙 / 竖墙矩形 = 中心线 + 原图的墙厚（不套 240/120 模板）。
  - 门窗：同一直线上两段墙之间的缺口；缺口里有 ≥2 条平行细线 = 窗（外墙）/推拉门（内墙），旁边有 1/4 圆弧 = 平开门（铰链和开向取自圆弧）。
  - 房间名：OCR 读到的字 + 位置（不按“三房两厅”模板补，不编没有的房间）；房间范围 = 以名字为种子、跨线代价高的最短路分区。
  - 家具、洁具、门扇、玻璃、隔墙细线：骨架化后**按原图描成多段线**（`traced_lines`，家具图层），所以和原图一模一样。
  - 墙只认实心墙（黑色/深色填充带）。空心双线墙、彩色效果图、照片的外轮廓闭合不了（<50%），描图器会**拒绝**，自动退回下面的
    墙网格流程（尺寸数字先用 RapidOCR 读链的裁图，读不出才问一次视觉模型）。
- **`drawing_build` 硬核对（traced 图）**：把生成的图按比例画回原图像素上比对，以下任何一项不合格都是 errors，附 `diff.png`
  （红 = 原图有没画、蓝 = 画了原图没有）：
  - 实心墙：墙精度 ≥93%、覆盖率 ≥90%（±约 30 mm）；
  - **空心墙**：原图里接着实心墙、用两条细线画的墙段（同一中心线、同样厚度）必须作为墙画出来（`hollow_walls`，墙体图层，
    照原图画成两条线）——实心墙比对看不见它们，所以单独查；柜子、床的双线不算；
  - **全图墨线覆盖**：平面范围内原图的所有线条（墙 + 家具 + 门窗线）≥90% 要出现在图里，漏画的位置列出来；
  - 原图上 OCR 到的每个房间名都要画出来，且落在自己的房间里；总尺寸与原图一致。
  **不再用视觉模型看 overlay 说“基本一致”。** 描出来的墙不要手改；不合格就重跑 `drawing_auto`，最多 3 轮，仍不合格就交付并把错误列为待确认。
- **交付**：`plan.png`、`plan.pdf`、`plan.dxf`、`plan.dwg`（ODA File Converter 转 ACAD2018，**转完再转回 DXF 比对图元数、图层、范围**，
  不一致就不交 DWG 并说明）、`diff.png`。电脑上没有转换器时 `drawkit.py ensure` 会自动装到 `~/tools/ODAFileConverter`（x86-64），
  或 `bash deploy/vm/cad-drawing-setup.sh dwg`。全部在电脑（VM）上，不进 API 的 Docker 镜像。
  装好后 `python3 drawkit.py ensure` 会真转一张带中文名的小图（`dwg_works`）；DWG 没生成时报告里会写出 ODA 自己的报错，
  `python3 drawkit.py dwgtest` 逐种启动方式（xvfb-run / DISPLAY / offscreen）试一遍并打印结果。不要说"本机没有转换器"，照报告原话说。

## 铁律（3.8.8 / 3.8.9）
- **每个新任务都是全新的活**：只在本任务的文件夹里工作（`cad/` 就是本任务自己的 `tasks/<任务id>/cad`）。
  **绝不**复制、重发或从以前任务的输出（spec、dxf、png、pdf、修好的图）开始——**上传文件 md5 和以前一样也不行**，
  不要拿 md5 去找旧结果。示例 spec 只是写法示例，不能当成交付或起点。只有在同一张任务卡上“继续/修改”才沿用该任务的文件夹。
  与别的任务交付过的文件字节完全相同的文件，send_file 会被拒绝。
- **阶段是代码强制的**：READ（最多约 8 步看图/裁图/像素扫描）→ SPEC（必须写出 cad/spec.json）→ BUILD → VERIFY（≤3 轮）→ DELIVER。
  读图预算用完后读图工具会被关掉，只能根据已有 FACTS 写 spec。
- **发现马上记下**：每读到一条尺寸链、一个标签位置、一组墙线，就 `drawing_note` 记进 `cad/facts.json`。FACTS 每一步都会
  显示在任务说明里（旧步骤滚出历史也不会丢）；`confirmed=true` 的会锁定，不要重读。`drawing_read` 两遍一致的链自动记入并锁定
  （调用时写上 `side`）。
- **不要用自由提问问视觉模型“标签在哪”**：标签位置用 OCR 或一次带像素网格的 JSON 读取，`drawing_auto` 自动做。
- **spec 记录来源**：`source.md5`（原图 md5）和 `source.task`（写它的任务）。与当前上传或当前任务不符时，`drawing_build` 报
  `STALE SPEC`，修订开始时旧 spec 会被移到 `cad/_stale/`——按当前图重新出草稿。
- 连续几步在重复同一个分析、什么新东西都没写，会收到「停止分析，立即根据已有 facts 写 spec 并生成」。

## 确定性流水线（3.8.9，task-3fc 之后）
- **不要猜像素框。** `drawing_auto` 自己找四条尺寸链：外墙外侧的细长线 + 线上的刻度（尺寸界线穿过或圆点/斜杠），
  数字用 tesseract（≤20 秒）读，读不出时服务器对每条链的裁图问一次视觉模型（严格 JSON）。你只需（可选）给数值
  `chains: [{side, values}]`；对边总和、x/y 比例、外墙框长宽比自动核对，每个轴单独拟合比例。
- **房间来自墙网格**：粗墙像素（彩色户型图的深灰墙带、双线墙）→ 轴网（吸附尺寸链刻度）→ 每条格边测墙覆盖 →
  直角、不重叠的房间；同一连通区里有多个标签时，按“穿墙代价”分给最近的标签（门洞不会把两个房间并成一个）。
  门放在内墙缺口处，外墙缺口有玻璃线的是窗。**你的工作只是名字**：标签 + 大致像素位置（OCR / 一次 VLM 读 / 你第一次读图）。
- **`drawing_build` 自动修**：某条链各段同比例偏差（框到了别的线）或量出 ~0（没框到线）→ 按数值在图上重新定位这条链；
  房间有斜边/面积为 0/重叠 → 按墙网格重建房间、按位置保留名字（原文件存为 `*.before-repair.json`）；
  门窗不在墙上 → 吸附到 1 m 内最近的墙边，太远就不画并列入待确认；尺寸数字避开尺寸线。另外输出 `plan.pdf`。
- **一定收敛**：看图预算按阶段算（BUILD/VERIFY 每轮最多 4 次针对报错的读取）。卡住时说实话（「spec 已生成但核对未通过：
  左链第1段…」）；用户点「继续」= 计数清零、新预算、并直接跑确定性流水线（自动链 → 网格房间 → 已读到的名字 →
  生成 → 自动修），之后一段时间内不会因同一原因再暂停。最多 3 轮核对后交付最好的草稿（DXF/PNG/PDF）+ 待确认清单 + 精度说明。
- 纯文件阶段（READ/SPEC/BUILD）不再每步截桌面 + 视觉描述；OCR 调用超过 20 秒就放弃并改用视觉读取。

Agent 里有两个专用工具，优先用它们：
- `drawing_read`：把源图某一块放大，用视觉模型**读两遍**（两种问法），自动比对；不一致会再放大读第三遍并告诉你冲突在哪。
- `drawing_build`：按 spec 重新生成整张图（DXF + PNG + 叠图 overlay + report.json），在 LibreCAD 里打开，返回检查结果。

命令行（在电脑上，`D=~/workspace/.aiw/cad-drawing` 或 `~/.claude/skills/cad-drawing`）：
```bash
python3 $D/drawkit.py ensure                         # 缺 numpy/Pillow/ezdxf/中文字体就自动装
python3 $D/drawkit.py zoom IMG --box x0,y0,x1,y1 --k 6 [--rotate 270] [--grid] --out cad/crops/left.png
python3 $D/drawkit.py ticks IMG --side left --box x0,y0,x1,y1   # 尺寸线 + 刻度/尺寸界线的像素位置
python3 $D/drawkit.py fit cad/spec.json              # 像素↔mm 拟合、逐段残差、对边闭合检查
python3 $D/drawkit.py axes cad/spec.json --out cad/axes.png      # 轴网画在原图上，看是否压在墙上
python3 $D/drawkit.py auto IMG [--chains values.json] [--labels L.json] [--from-spec old.json] --out cad/spec.json --debug cad/auto_debug.png
                                                     # 确定性草稿：自动找尺寸链（刻度+数字）+ 墙网格房间 + 门窗缺口；
                                                     # values.json 只需 {"chains":[{"side","values"}]}；退出码 3 = 找到链但数字没读出（need_values）
python3 $D/drawkit.py build cad/spec.json --out cad --name plan  # 全量生成 + 检查（退出码 2 = 有错误）
python3 $D/drawkit.py schema                         # spec 字段说明
```

## 步骤清单（每张图都按这个顺序；楼层平面以外的图见最后一节）

### A. 把源图读准（不准就停在这一步，不要开始画）
1. 看全图一次：图名、户型/零件名称、有几条尺寸链、房间/部件大致位置。记下图中平面所在的像素范围。
2. **一条尺寸链一条链地读**：对每条链（上、下、左、右，外圈、内圈）用 `drawing_read`（region=该链的像素框，
   kind=chain；竖向的链自动旋转成横排再读）。它读两遍并比对；两遍一致才算数。不一致：缩小框、放大倍数加大再读，
   **不要猜，不要取平均**。
3. 交叉校验：
   - 对边的链总和必须相等（上=下，左=右）。不等时，要么某个数读错了（回到第 2 步，对那一段单独放大），
     要么确实有退台/凸出——在 spec 里用 `explain` 写清楚是哪一段退了多少。
   - 用刻度的像素位置核对每一段：`fit` 会把写的数字和照片上量出来的长度比较。量出来差很多（>20%）几乎一定是
     读错了数字（例：示例照片左侧“3900”在小图上像“3000”，量出来是 ~3880；“1000”像“1600”，量出来 ~1010）。
     差 8–20% 通常是售楼图本身不按比例：保留标注值，并记进 `uncertain`。
4. 用户给的数字也要核对：用户转述的尺寸可能有错（示例中用户给的左侧 3000/1600 和右侧 5 段都与原图不符），
   以原图为准，并在交付时说明哪里和用户说的不一样。

### B. 轴网
5. 尺寸链的累计值就是轴线：x 轴来自上/下链，y 轴来自左/右链（y_down=true 时从上往下量，和照片同向）。
6. `fit` 用刻度像素拟合 像素↔mm（每个轴各一个比例和偏移），`axes` 把轴网画回原图：每条墙都应落在某根轴线上。
   x、y 比例相差 >3% 说明照片斜拍或某条链读错。

### C. 房间/构件 → spec
6b. **楼层平面照片：看一次全图后就 `drawing_auto`**（不用先手工读链、不要给像素框）。它自己找链和刻度、读数字、拟合比例、
   出墙网格房间和门窗，写出 `cad/spec.json` 草稿和 `cad/auto_debug.png`（红=识别的墙，色块=房间）。接下来**只改名字**
   （`房间?` 或放错的名字）和标题，然后 drawing_build。
7. 每个房间：名字取**图上的文字标签**（不要按模板“三房两厅”去套），位置取它在照片里的像素范围，按拟合的
   比例换成 mm，并吸附到最近的轴线；写成直角多边形 `poly`（或 `box`）。开敞的客厅/餐厅/玄关/过道给同一个
   `zone`，它们之间不画墙。
8. 门：落在房间边上，`at` 中心点、`width`、`into` 开向哪个房间、`hinge`；推拉门 `type: sliding`。
   窗：落在外墙上（照片上外墙里浅色/细线的那一段）。家具只画简单的块（床、沙发、餐桌、橱柜、洁具），不写字。
9. 每条事实都标 `confidence`；读不准的写进 `uncertain`（读到的值 + 用了哪个值）。spec 存到 `cad/spec.json`。

### D. 确定性生成（`drawing_build`）
10. 生成器从 spec 一次画完：墙（外 240、内 120 双线 + 填充，按轴线居中，门窗洞口自动切开）、门（门扇 + 开启弧线）、
    窗（四线）、家具、与原图一致的尺寸链（分段 + 总长两道）、房间名（放在多边形的“最远离边界点”，自动避开家具、
    门的开启范围和其他文字，放不下自动缩小字号）、图名、比例、说明/图例/待确认、图框和标题栏（都在平面范围以外）。
11. **永远整张重新生成**：要改什么就改 spec，再 `drawing_build`。不要用 ERASE 在 DXF 上打补丁，不要手工加坐标。
    LibreCAD 只用来给用户看、以及用户点名的极小手工修改。

### E. 客观核对（最多 3 轮）
12. 看 `report.json`：errors 必须为空（文字重叠、房间无标签、墙不闭合、门窗不在墙上、对边尺寸不闭合、数字与刻度不符）。
13. 看 `overlay.png`（生成的墙画成红色、房间名蓝色，按拟合的变换叠到原图上）：墙应压在原图的墙上。
    用 `read_image` 读一次 overlay，问具体问题：“红色墙线和照片里的墙哪几处没对上？哪个房间名放错了房间？”
14. 有偏差 → 改 spec → 重新生成。**最多 3 轮**；3 轮后还对不上的，写进 `uncertain` 和交付说明，不要继续循环。
15. 交付：`send_file` PNG、DXF（以及 PDF 如果有），done 里写：读到的尺寸链、与用户给的数字不一致的地方、
    检查结果、还不确定的点。

## spec 结构（JSON，单位 mm）

见 `drawkit.py schema`。要点：
```json
{
 "schema": "aiw-drawing/1", "kind": "floor_plan", "title": "…平面图", "subtitle": "三房两厅两卫 约108m²",
 "y_down": true,
 "source": {"image": "uploads/photo.jpg"},
 "chains": [
  {"side": "top", "values": [1300,1800,2800,3300,900], "reads": [[…第一遍…],[…第二遍…]],
   "box_px": [195,180,465,200], "confidence": "high"},
  {"side": "left", "values": [1200,3750,3850,3900,1000], "reads": [[…],[…]], "box_px": [182,200,206,480]}
 ],
 "walls": {"exterior": 240, "interior": 120, "railing": 100},
 "rooms": [{"id": "living", "name": "客厅", "zone": "public", "poly": [[3100,4800],[5900,4800],…]},
           {"id": "balcony", "name": "阳台", "type": "balcony", "box": [2700,11200,6500,13700]}],
 "doors": [{"at": [1300,5800], "width": 1000, "into": "entry", "hinge": "end"},
           {"at": [4600,11200], "width": 3000, "type": "sliding"}],
 "windows": [{"at": [4500,0], "width": 1800}],
 "furniture": [{"type": "bed", "box": [7300,2000,9100,3600], "head": "right"}],
 "notes": ["…"], "uncertain": ["…读不准的地方和采用的值…"]

```
完整例子：`examples/xinda-g-108.spec.json`（12 个房间、8 樘门、8 扇窗、19 件家具；本身就是回归测试的输入）。

## 不是户型图的时候（同一个思路：结构化 spec → 确定性生成 → 渲染 → 核对）
- **机械零件 / 节点详图**：`kind: generic`，`entities` 写轮廓线、圆、圆弧、中心线；`dims` 写尺寸（自动放到轮廓外侧）；
  `labels` 写标注文字（自动找不压线的位置并画引线）。先从照片读每个尺寸（同样两遍 + 像素核对），再写 spec。
- **接线图 / 流程图 / 框图**：`kind: diagram`，`nodes`（框、圆、菱形，文字自动缩放到框内）+ `edges`（正交走线、箭头、
  线上标签自动避让）。节点名字和连线关系从图上逐个读，不要按常识补。
- 其它（立面图、天花图……）：同样先列出构件、尺寸链和文字，存 spec；`generic` 能表达的都用它，生成后一样跑检查
  和叠图。生成器没有的元素，用 `entities` 的基本图元拼，不要改回逐条 cad_command。

## 经验（自进化：新的教训追加在这里，也会进 Aiw 学到的经验）
| 场景 | 问题 | 做法 |
|---|---|---|
| 照片读尺寸 | 一次问“所有尺寸”，前后两次答案不同（9300/9500），还自己编出九宫格布局 | 一条链一条链地放大读两遍；对边求和必须相等；用刻度像素量长度核对 |
| 照片读尺寸 | 小图上 3900 像 3000、1000 像 1600、两段 600 被读成一段 | 竖向链旋转成横排放大 6–10 倍；`fit` 量出某段与写的数差 >20% 就重读那一段 |
| 用户给的尺寸 | 用户转述的尺寸链有错 | 以原图为准，交付时明确列出不一致之处 |
| 布局 | 每一版布局都不一样（v6 和 v1–v5 完全不同） | 房间只来自图上的文字标签和像素位置，写进 spec；改动只改 spec 里那一项 |

## 3.9.6 补名字 / 补文字（续做任务）
- `source.transform` 是 **mm → 像素**：`px = ax*mm + bx`；像素换毫米要用 `mm = (px - bx) / ax`，不要反着乘。
- 开敞空间（客厅+餐厅+厨房+玄关之间没有墙）不要新加互相重叠的房间多边形；在 spec 里加
  `"free_labels": [{"text": "客厅", "at_px": [420, 950]}]`（或 `at` 用毫米），再 `drawing_build`。
- 确定性流水线（drawing_auto --from-spec）现在会保留旧 spec 的所有房间名和 free_labels，一个名字都不会丢；
  找不到房间的名字会自动变成 free_labels 并列入「待确认」。
