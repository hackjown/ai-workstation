# v3.9.71 引擎跑长任务（3.9.71 build 45）

起因：2026-11-22 用 huashu-motion 把 PPT 做成讲解视频，agy 和管家来回 8 轮只渲染出 70/2388 帧。

问题和修复
1. agy 单条命令同步只等约 10 秒，长渲染只能放后台；但 AIW 默认规则不允许 nohup / 重定向 / &，被拦后只能分批前台跑，每批都要冷启动 Chrome（约 50 秒）。
   → 默认允许：`[setsid [-f]] [nohup] bash|sh|python|node 脚本 [参数] [> log] [2>&1] [&]`（参数里不能有 ; & | ` $ < >），以及 ps/pgrep/nproc/free/uptime/df/top -bn1、ffmpeg/ffprobe。
   用 setsid 起的进程脱离 agy 的进程组，AIW 重启会话（允许/放开权限/换模型时会 killpg）也不会把渲染杀掉。
2. 读技能文件被拦（~/.claude/skills/... 在工作文件夹外）。→ 默认允许读 ~/.claude/skills/**、~/.agents/skills/**、~/.npm/_npx/**。
3. 被拒操作显示成「?」。→ 没有常见字段时取参数里第一个字符串。
4. 管家选了 20~30 分钟的纯 Chrome 渲染（方案 A），没选 1 分钟能出片的 FFmpeg 合成（方案 B），又让它前台分批手跑、追问同一件事。
   → 管家规则加三条：长命令写成脚本 setsid nohup 后台跑、之后只看日志；几个方案选几分钟内能交付的，一小时以上先问用户；同一卡点两轮没进展就换做法。

还没解决
- 「browser is gone」（第 264 帧 Chrome 崩溃）多半是 VM 内存不够（4 核、无 GPU、SwiftShader 软渲染），VM 内存加到 8G 后再看。
- 默认规则写在 ~/.gemini/antigravity-cli/settings.json；有人说 headless 只读 ~/.gemini/config/config.json，未核实。
