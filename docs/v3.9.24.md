# v3.9.24 进阶功能：模型路由、自动审核、Webhook、用量统计、应用、提示词、上下文、教学录制、远程访问、自动签到

基于 v3.9.23。部分思路参考 ProkBot（gitee.com/ahaduoduoduo/ProkBot），它的许可证是非商用许可，这次只借鉴了思路，代码全部重写，没有复制它的任何代码。

所有新功能都有开关。默认要么是关闭的，要么内容为空。不配置的话，任务、聊天和授权卡片的行为和 v3.9.23 完全一样。网页入口在「设置 › 进阶功能」，每项一个页面，沿用原来的深色风格。

## 2. 自动模型路由
- 任务开始前先判断难度，分成简单 / 普通 / 困难三档。先看你写的规则（正则 => 档位），再用内置的关键词和长度打分。开启「用小模型判断」后，规则拿不准时再调用一次小模型，约 80 个 token。
- 每档可以设一个模型和推理强度。推理强度有四个选项：默认、低、中、高。低、中、高以 `reasoning_effort` 发给网关，网关返回 400 时自动去掉这个参数重试。某档的模型留空，就用主模型，只改推理强度。
- 手动指定的模型永远优先。`POST /api/tasks` 新增 `model`、`effort` 两个字段，续做时沿用第一次的选择。视频任务仍然用视频模型。
- 显示：任务时间线上会多一条「模型路由：困难 → xxx · 推理强度 高（原因）」，网页和 iOS 都能看到。`GET /api/tasks/{id}` 返回 `route` 和 `model_pick`。
- 「聊天也按难度选模型」默认关闭。
- 设置存在 kv `autoroute`。接口：`GET/PUT /api/autoroute`，`POST /api/autoroute/test`。
- 开关：`AIW_AUTOROUTE=0` 强制关闭，`=1` 强制开启。

## 3. 自动审核
- 只作用于原来会弹授权卡片的操作，判断顺序如下：
  1. 拒绝规则。命中就直接拒绝，而且永远优先，比「本任务内都允许」和模型的判断都优先。
  2. 付款、发消息或发布、下单（order_confirm）、小红书审核（xhs_review）一律照常弹卡片。
  3. 允许规则。命中就放行。
  4. 开启「用模型审核」时，交给模型判断，结果是 allow、ask 或 deny，并附理由。关掉「模型可直接拒绝」后，deny 改为弹卡片。
  5. 以上都没有结论，或者出错、超时（`AIW_AUTOREVIEW_TIMEOUT`，默认 20 秒），照常弹出原来的卡片。
- 规则每行一条，匹配「工具名 + 命令、网址或路径」。写法：`shell:git *`（工具前缀加通配符）、`*rm -rf /*`、`re:正则`。以 # 开头的行是注释。
- 每次决定都记在 review_log 表里，页面上能看到最近的记录。时间线上显示为「by: review」。有「试一试」按钮，只模拟、不记录。
- 接口：`/api/autoreview`、`/api/autoreview/log`、`/api/autoreview/test`。
- 开关：设置里默认关闭；`AIW_AUTOREVIEW=0` 强制关闭。

## 4. Webhook 触发
- 调用 `POST /api/webhooks/{id}` 不需要 API Token，靠签名鉴权：
  - 请求头 `X-AIW-Timestamp: <unix 秒>`
  - 请求头 `X-AIW-Signature: sha256=<HMAC-SHA256(密钥, "时间戳.原始请求体")>`
- 时间戳必须在 ±5 分钟内（`AIW_WEBHOOK_WINDOW_S`），同一个签名只接受一次，重放返回 409。请求体必须是 JSON，最大 256 KB。
- 任务模板里可以用这些占位符：`{{payload}}`（整个 JSON）、`{{payload.a.b}}`（单个字段）、`{{name}}`、`{{now}}`。模板里没有占位符时，JSON 会附在模板后面。
- 每个 webhook 的密钥存在加密保险箱里，名字是 `webhook_<id>`，只在创建或轮换时显示一次。管理页可以新建、启用或停用、轮换密钥、删除、查看最近 200 次调用，还附有 curl 和 openssl 签名示例。
- 开关：`AIW_WEBHOOKS=0` 关闭公开入口，返回 404。

## 5. 每日 token 统计
- 每次模型调用都记一行：日期（北京时间）、模型、角色、任务、输入和输出 token。角色分为任务主模型、聊天、小模型、看图、子代理、审核、定位。
- 数据来自网关返回的 usage。流式请求加了 `stream_options.include_usage`；网关不支持时，用 `AIW_USAGE_STREAM=0` 关掉。网关不返回 usage 的调用不计入统计。
- 接口：`GET /api/usage?days=14`（按天、按模型、按角色汇总，加上最耗 token 的任务）、`GET /api/usage/task/{id}`、`DELETE /api/usage?before_days=90`。
- 网页：「进阶功能 › 用量统计」。iOS：「设置 › 用量统计」，新文件 `apps/ios/Sources/V3924Views.swift`。
- 开关：`AIW_USAGE=0` 停止记录。

## 6. 应用（单个 JSON 文件）
- 格式：`"aiw_app": 1`，加上 id、name、version、description、kind，kind 有三种：
  - `code`：在任务所在的电脑上运行。文件写到 `~/workspace/aiw-apps/<id>/<版本>/`，setup 只运行一次。参数以 JSON 从 stdin 传入，stdout 就是结果。任务里的工具名是 `app_<id>`。
  - `mcp`：远程 MCP 服务器。鉴权方式有 none、api_key、bearer、oauth，密钥只写保险箱里的名字。oauth 支持 client_credentials 和 refresh_token 两种授权方式，会自动换取并缓存 token；浏览器授权码流程没有做。
  - `skill`：技能说明。请求里提到应用名、id 或关键词时，才把说明放进任务提示词；也可以设成 always（每个任务都放）。
- JSON 里出现密钥字段（token、key、password 等）时直接拒绝导入。导出的 JSON 里也只有密钥名字。
- 内置工具「编写应用」（`write_app`）：Agent 可以把做好的功能写成应用。保存后是**草稿（未启用）**，你在「进阶功能 › 应用」启用后才生效。
- 应用页可以导入（粘贴或选文件）、启用或停用、测试（MCP 会列出它的工具）、导出、删除、填写需要的密钥。
- 开关：`AIW_APPS=0` 关闭所有应用。

## 7. 提示词管理
- 可以管理的角色：任务 Agent、任务规划、子代理、小秘聊天、聊天分流、聊天滚动摘要、模型路由分级、自动审核、教学→技能。
- 每个角色都能查看原版，编辑后保存为新版本并启用，最多保留 30 个版本，可以切换到任意版本，也能一键恢复原版（版本不会删除）。
- 聊天提示词里的占位符 `{name} {now} {tools}` 写错时，自动回到原版，不会报错。
- 「某个任务实际收到了什么」：每次运行记录每个角色收到的完整系统提示词（含技能、电脑等附加段落）、工具列表、模型，以及是否用的是你的版本，存在 kv `prompt_trace:<task>` 里。只有 v3.9.24 之后的任务才有这份记录。
- 开关：`AIW_PROMPT_OVERRIDES=0` 时，全部角色临时回到原版。

## 8. 每个模型的上下文设置
- 每个模型（或模型名前缀，`*` 表示默认）可以设：上下文窗口、触发比例（或直接填触发 token 数，后者优先）、保留最近几步。
- 每一步发给模型之前，先估算「系统提示 + 任务 + 最近 25 步」的大小。超过阈值时，较早的步骤压成每条一行，最近 N 步保留原文；已经超出 25 步窗口的步骤，汇总成一行写明做过哪些工具。事实板（findings）不压缩。
- 压缩是确定性的截短，不额外调用模型。token 数是估算值：中文约 1 字 1 token，其它字符约 4 个 1 token。
- 没有设置的模型完全照旧。接口：`GET/PUT /api/model_context`。开关：`AIW_CONTEXT_MANAGE=0`。

## 9. 教学录制（演示一遍 → 技能）
- 「进阶功能 › 教学录制」点开始，然后在「电脑」页点「接管桌面」，正常操作一遍。会记录：
  - 接管输入层的每个操作，包括点击、拖动、滚动、按键、输入的文字，以及时间和坐标；
  - 截图：每次点击或回车后截一张，屏幕有变化时最多每 4 秒截一张（`AIW_TEACH_SHOT_S`），所以直接在 noVNC 画面里操作也有截图；
  - 你边做边写的备注。
- 停止后可以让模型写 SKILL.md，会先用看图模型描述几张关键截图。录制中输入的账号、密码要求模型写成 `{{占位符}}`，也可以勾选「把输入的文字打码后再交给模型」。
- 生成的内容由你检查修改后再保存：保存为技能应用（立即启用）；可选同时写到那台电脑的 `~/.claude/skills/<名字>/SKILL.md`，并登记为自定义技能。
- 截图存在 `artifacts/teach/<id>/`。录制上限 1 小时（`AIW_TEACH_MAX_S`）、300 张截图、5000 个操作。
- 开关：`AIW_TEACH=0`。

## 11. 远程访问
- 一个页面汇总所有访问方式：
  - 局域网 IP。在 Docker 里显示的是容器地址，可以设 `AIW_LAN_IP`，或在页面里填真实地址。
  - Tailscale。容器里有 tailscale 命令时自动读取 IP，否则手动填写。
  - 自己的 HTTPS 反向代理地址。
  - 内置隧道。
- 内置隧道用 Cloudflare quick tunnel（`cloudflared tunnel --url`）：不用注册账号，不用开端口，会得到一个随机的 `https://xxx.trycloudflare.com` 地址，每次开启都会变。
  - 必须先设置 `AIW_API_TOKEN`，否则拒绝启动。隧道后面的所有接口照常需要令牌登录。
  - 镜像里没有自带 cloudflared。页面上点「安装」，会从 GitHub releases 下载到数据目录 `bin/cloudflared`（约 30 MB）。也可以用 `AIW_CLOUDFLARED` 指定已有的程序，或用 `AIW_CLOUDFLARED_URL` 指定镜像地址。
  - 可以设成随服务一起启动。
- **国内可达性**：trycloudflare 走 Cloudflare 国际网络，在大陆访问经常很慢，有时连接被重置或打不开；quick tunnel 本身也没有可用性保证，下载 cloudflared 也依赖 GitHub。长期稳定使用请选 Tailscale 或自己的 HTTPS 反代。
- 推送仍然只用 Bark，没有加 APNs。
- 接口：`GET/PUT /api/remote`、`POST /api/remote/tunnel/start|stop|install`。开关：`AIW_REMOTE_TUNNEL=0` 禁用内置隧道。

## 自动签到
- 没有预置任何网站，在「进阶功能 › 自动签到」里添加：名称、签到页网址、时间（cron.py 语法，默认 `daily 08:30`）、随机延后 0–N 分钟（默认 15）、用哪台电脑、给 Agent 的说明。
- **第一次签到**由 Agent 在那台电脑已登录的浏览器里完成，并用内置工具 `checkin_save_recipe` 保存「配方」，有两种：
  - browser 配方：步骤有 open、click（按钮文字）、fill、wait、expect（签到成功后页面上应出现的文字）；
  - http 配方：一串请求，cookie 和 token 从保险箱读取，配方里不能写密码。
- **之后**每天按配方直接重放，不调用模型：
  - browser 配方在电脑的 Chrome 里执行。expect 步骤通过 VM 上已有的 vm-agent CDP 模块读取页面文字。
  - http 配方从 AIW 服务器发出请求。
- 重放失败时，这次交给 Agent 签到，它也可以保存一个更好的配方。页面上有「重新录制」按钮，会清掉现有配方，下次重新录。
- 遇到验证码、滑块、短信验证：**绝不绕过**。Agent 用接管请求让你来处理，同时推送一条「签到需要你」。
- 同一轮调度到期的网站算一批，整批只推送一条 Bark 汇总，例如「自动签到 3/4 成功」，再加每个站一行。
- 页面上能看到每个站的状态、下次和上次签到时间、历史记录，还有「立即签到」按钮。iOS 也能看站点列表和点「立即签到」。
- 接口：`/api/checkin/sites*`、`/api/checkin/runs`、`/api/checkin/settings`。开关：设置里的「开启自动签到」；`AIW_CHECKIN=0` 停止定时签到，手动签到仍然可用。

## 部署
1. **应用顺序**：v3.9.22 → v3.9.23 → v3.9.24。这个包只包含相对 v3.9.23 改动或新增的文件，前两个包要先解压覆盖。在 Mac 上照旧操作：`rsync -a --exclude .git ... ai-workstation-main/ ./`，不要加 `--delete`。
2. **aiw-api 镜像需要重建**（代码打包在镜像里）：`docker compose up -d --build aiw-api`（用预构建镜像的话等新镜像发布后 `docker compose pull && docker compose up -d`）。**没有新的 Python 依赖**，requirements.txt 没有改动。cloudflared 不在镜像里，需要时在页面上安装，存到数据卷。
3. **VM 不需要运行 update-agent.sh**：这次 vm-agent 没有改动。代码应用、签到配方、教学录制都只用已有的命令（files.write、shell.exec、browser.open/click/fill、computer.input、截图）。签到的 expect 步骤会调用 VM 上 `~/ai-workstation` 里已有的 CDP 模块；VM 的代码太旧、读不到页面文字时，重放会判为失败并交给 Agent，这种情况下再跑一次 update-agent.sh 即可。
4. **数据库**：新增 token_usage、review_log、webhooks、webhook_calls、checkin_sites、checkin_runs 六张表，启动时自动创建，旧表不变。
5. **网页**：新增 `apps/web/v3924.js`，index.html 里加了一行 script。浏览器如果缓存了旧页面，刷新一次即可。
6. **iOS**：新增 `V3924Views.swift`，在 SettingsView 里加了「用量统计」和「自动签到」两个入口。这里没有 Xcode 和 Swift 编译器，**没有编译过**，请在 Mac 上用 build-ipa.sh 编译后再装。

## 已知缺口 / 没测到的
- iOS 没有编译。网页只用 node 做了语法检查和渲染冒烟测试（用样例数据跑通 10 个页面），没在真实浏览器里点过。
- 模型路由、自动审核模型、教学写技能，都只用脚本化模型做了测试，没接真实网关试过。`reasoning_effort` 在你的 uniapi、DeepSeek、GLM 网关上是否生效没有验证（不支持时会自动去掉）。
- 流式聊天的 usage 依赖网关支持 `stream_options.include_usage`；不支持的网关，聊天回复的 token 会漏记。
- MCP 应用的 OAuth 只支持 client_credentials 和 refresh_token，浏览器授权码流程没有做。
- 教学录制只能看到「接管桌面」输入层里的操作。直接在 noVNC 画面里点击、或 Agent 自己的操作，只能靠截图；VM 端的全局键鼠记录没有做，那样需要更新 vm-agent。
- 签到的 http 配方从服务器发出请求，需要你把 cookie 或 token 放进保险箱，因为 Agent 拿不到浏览器 cookie 的值。browser 配方的 expect 依赖 VM 上 Chrome 开着 9222 调试端口。真实网站上没有测过。
- 内置隧道在沙箱里没有真正连通过（没有网络），只测了缺少程序、没有令牌和关闭开关这几种情况。
- 上下文压缩是截短，不是语义摘要；token 数是估算值。
