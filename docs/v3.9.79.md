# v3.9.79 群聊按步骤分工

问题（四引擎测试群）：
1. 管家把用户写的分工改了：@ 在交给模型前被删掉，模型看不到谁做哪步，把第 4 步给了 CodeBuddy、第 5 步给了 Muse。
2. 所有成员同时开工，Muse 一开始就要第 2–4 步的结果。
3. 云端成员只拿到自己的任务，看不到群里前面的结果；Cue 以为要自己去群里发消息，操作被拒绝。
4. 本地成员各在自己从基线开出的分支上，后一步看不到前一步写的代码。

改动（services/api/aiw_api/bot_groups.py）：
- parse_steps：消息里有两步以上「第 N 步 / 1. … @成员」时直接按写的执行，每步带上总目标和末尾的「规则：」。
- 没写明步骤时，模型拿到带 @ 的原文；提示词要求照用户分配，有依赖时输出 steps。
- bot_groups.queue 存待做的步骤；成员回复后才交下一步。失败（turn_failed/blocked）就暂停，「@管家 继续」接着做；「停止」清空。
- 每一步的任务都带上本轮前面成员的回复（每条最多 2500 字，共 6000 字）。
- 本地成员开工前，管家把前面本地成员的分支合进它的分支；冲突时让它自己先 git merge。
- 「@管家」的步骤：合并本地分支，在合并工作树里运行任务里写的检查命令（白名单：pytest、python3 x.py、node、npm test、go test、cargo test、ls、cat、wc；不允许 ; & | $ 等），再根据群聊记录和输出写汇报表。合并冲突时先交回成员修，修完再汇报。

测试：tests/test_v3979_group_steps.py（6 个）。test_v3961_groups.py 的 5 个失败是原有的。
