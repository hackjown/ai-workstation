# v3.9.82 用 @ 指定引擎；群聊分工的职责边界

## 主聊天
| 你在主聊天输入 | 去哪 |
|---|---|
| 查询 agy 的 ldok 开发进度（不带 @） | AIW 自己回答：查进度、看对话记录、改默认模型，不会给引擎下指令 |
| @agy 查一下 ldok 的进度 | agy 的单聊（带单聊上下文，用 agy 的默认模型） |
| @agy 新建任务，做一个天气小程序 | agy 新建任务 |
| @agy 继续 ldok 任务，增加导出功能 | 按标题或文件夹名找到 ldok 任务接着做 |
| @agy 在 ~/workspace/x 里写个 hello | 在那个文件夹开任务 |
| @agy @codex 一起做登录页 / @所有引擎 … | 群聊任务 |

- 选引擎：输入框里打 @ 弹出引擎列表（显示本地/云端、是否在忙、默认模型），或 + 号里点「引擎 @」。选中的引擎是蓝色标签，发送时变成「@agy …」。
- 网页和 Android（同一套 WebView 页面）、iOS 主聊天都改了；iOS 需要 CI 编译。
- 「让 agy …」「交给 codex …」这类自然语言不再自动派活，主聊天的模型也不再有 engine_task 工具。

## 群聊分工（根据 bg-f16b8b9c 的验收汇报）
- 管家验收时跑的命令改用 bash 执行，不再出现 `/bin/sh: Bad substitution`（PIPESTATUS 是 bash 才有的）。
- 每个本地成员的一步开始前记下起点提交，做完后算出它改了哪些文件，记到它名下；后面的成员改了前面成员负责的文件（如实现方改了 SPEC.md 或测试），管家在群里提示“建议原负责人复核”，验收汇报里会看到。
- 给本地成员的任务说明加了：只做这一步要求的改动，别人负责的规范/测试有问题就在回复里提，由管家交回。
- 云端成员（Muse、Cue）轮到审查时，管家把前面步骤产出的文件内容（只读副本，最多 40 KB）附在任务里，审查不再只能写“需核对”。
- 管家分工的规则加了：写规范的步骤要一次钉死输入范围、边界、输出格式、退出码、警告格式；实现的人不改规范和测试。
