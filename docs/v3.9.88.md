# v3.9.88 引擎群聊：借鉴 t3code 的七件事

参考 https://github.com/pingdotgg/t3code（MIT）的 Workflows、源码管理和权限模式。网页和 iOS 都做了。

1. **可恢复**：群里正在做的那一步记在 `bot_groups.cur`。API 重启时 `Groups.recover()`：
   - 管家自己的步骤（汇总、截图、验收、推送）直接重跑；
   - 成员的回复在停机期间已经到了，就补进群里接着走；
   - 成员那一轮被重启打断，先停掉它，再把同一步重新交给它；
   - 正在盯的 PR 接着盯。
   管家步骤出错自动重试 3 次（30 秒、2 分钟、10 分钟后），还不行就停下等你。成员没做成就停在那一步：
   「重试这一步」（或「@管家 继续」）重新交给它，「跳过这一步」接着做下一步。注意：「继续」以前是跳到下一步，现在是重试。
2. **带理由的选择**：每个按钮下写着点了会怎样。选设计时可以「都不要，重做」，必须写理由（或回复“都不要，理由是…”），
   设计的人带着理由重出一轮，最多 3 轮。确认方案时可以「改一下方案」写上怎么改，管家改完再给你确认。
3. **需要你**：群聊列表把等你的群排在最前，写明等你做什么（确认方案、选设计、选交付、允许被拦的命令、处理没做成的一步）。
   `GET /api/bots/groups-needs`。
4. **开 PR**：推送 `aiw/<群>/merge`，实测截图推到 `aiw/<群>/shots`，用电脑上的 `gh` 开 PR。
   标题和说明由管家根据定稿方案、验收报告、跑过的命令写，附审阅导览和截图。已有 PR 就更新说明。
   电脑上没有 `gh` 或没登录时，分支照样推送，并给出手动开 PR 的链接。
5. **盯 PR**：每 2 分钟看一次。
   - CI 失败：拿失败日志，交给负责的成员修，然后合并再推送，最多 3 次。
   - 和基线冲突：交给成员合并解决。
   - 别人的新评论：需要改代码的交给负责人，改完推送。
   - CI 全绿时告诉你。
   PR 合并或关闭就停。连续 10 次只有评论，或连续 8 次读不到状态，也会停。
6. **只看这一轮的改动**：成员每轮做完，记下这一轮自己提交改过的文件（`git log --no-merges`，它合进来的别人的改动不算）。
   回复下面有「看这一轮改动」；菜单里有「和基线整体对比」。`GET /api/bots/groups/{gid}/diff?msg=…|whole=true`。
7. **群里直接处理权限**：agy 被权限拦住时，在它的群消息上直接「允许这类命令再试 / 这一轮放开 / 拒绝」，允许后它接着做，
   后面的步骤也接着走。其他引擎给出跳到它对话的入口。`POST /api/bots/groups/{gid}/permit`。
8. **审阅导览**：验收报告里按阅读顺序列出 3～8 站，需要人拍板的标「要仔细看」，机械改动单列。PR 说明里也有。

未验证：iOS 未编译；没有在真机和真实 GitHub 仓库上跑过；`gh` 要在电脑上装好并登录。
